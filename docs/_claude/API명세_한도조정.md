# 한도 조정 API 명세

> ⚠️ **초안(미확정) — 리뷰 대상 아님.** 서버 파트 작업 문서의 백업이며, 구현하면서 확정하면 이 배너를 지우고 그 구현 PR에 포함한다. 팀이 보는 명세는 노션 "API 설계"뿐.
> 대응 화면: 챌린지 조정(경고 카드 GOAL_TOO_TIGHT의 진입점). 옵션은 **3개 고정 확정**(현재 유지 / +10% 여유 / +20% 여유 — 자유 입력 없음), **챌린지당 최대 2회**, 하향 없음(화면에 없음 — 자체 결정).
> 과거 기록 유지는 화면 문구로 확정: "이미 지난 N일 기록은 그대로 유지되고, 앞으로의 한도만 바뀌어요".
> 상태: 초안 · 구현: ⏳ 미구현(이슈 #7) · 공통 규약은 `API명세_본챌린지.md` §0.

## `POST /api/challenges/{id}/adjust` — 목표(하루 한도) 조정 🔒

**요청 바디** — 금액 대신 **옵션**을 받음(클라·서버 라운딩 불일치 방지). "현재 유지" 선택은 호출 없음.

| 필드 | 타입 | 필수 | 제약 / 설명 |
|---|---|---|---|
| option | string | ✅ | `PLUS_10` / `PLUS_20` — 서버가 현재 한도 × 1.1 / 1.2로 계산, **버림(floor)** — ✅자체 결정(하루 한도와 동일 규칙) |

**서버**: 새 한도 계산 · `challenge_adjustment` 이력 추가(old/new) · `challenge.daily_limit` 갱신 · **과거 `challenge_day` 판정은 소급하지 않음**(각 행의 `daily_limit` 스냅샷 유지 — 화면 확정) · 이후 판정·절약/초과 계산은 날짜별 스냅샷 기준.

**응답 `200 OK`**

```json
{ "challengeId": 1, "dailyLimit": 27500, "usedCount": 1, "maxCount": 2 }
```

**에러**

| 코드 | 상황 |
|---|---|
| 400 | option이 PLUS_10/PLUS_20 아님 |
| 401 / 403 / 404 | 공통 |
| 409 | 조정 횟수 소진(2/2) · 챌린지가 IN_PROGRESS 아님 |
