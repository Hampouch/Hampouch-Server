## 아키텍처·연동 (Claude 판단)

- **지출 데이터 = 령준이 조회 메서드 제공, 일혁이 호출** — 직접 SELECT는 령준 테이블 구조 바뀌면 같이 깨져서 배제. `POST /days`는 테스트/시드 전용으로 강등.
- **'오늘 남은 한도' = 일혁이 조회 메서드 노출, 령준이 호출** — 지출 입력 화면의 "지출 후 남은 한도"용.
- **집중(약한) 카테고리 = varchar 저장, FK 안 씀** — 이름만 저장, 결과 집계는 령준 데이터에서. 양쪽이 같은 7종 이름만 쓰면 됨.
- **위젯 = `GET /current` 재사용** — 전용 경량 API는 안드가 무겁다 하면 그때.
- **월급날 = `reset_by_payday`·`payday_day` 저장** — 화면에 입력 있음. 리셋 '동작'은 그 기능 만들 때 기획 확인.
- **다음 챌린지 추천 = 규칙 기반(직전 결과 ±%) 먼저, AI는 나중** — % 공식은 기획(PM). AI 인프라 공용화는 AI 기능 확정 후.
