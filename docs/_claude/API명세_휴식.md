# 휴식 API 명세

> ⚠️ **초안(미확정) — 리뷰 대상 아님.** 서버 파트 작업 문서의 백업이며, 구현하면서 확정하면 이 배너를 지우고 그 구현 PR에 포함한다. 팀이 보는 명세는 노션 "API 설계"뿐.
> 휴식 = 챌린지 일시정지가 아니라 **챌린지 사이의 공백(유저 단위)**이다(2026-07-06 재해석 — 이전 판의 PAUSED 상태·기존 API 4곳 변경은 철회).
> 상태: 초안 · 구현: ⏳ 전부 미구현(후속 이슈) · 공통 규약(경로/인증/응답·에러 포맷)은 `API명세_본챌린지.md` §0.

## 1. `POST /api/rests` — 휴식 시작 🔒 ⚠️

대응 화면: 휴식 시작("잠깐 쉬어갈까요?"). **유저 단위** — 챌린지 리소스 하위가 아님.

**요청 바디**

| 필드 | 타입 | 필수 | 제약 / 설명 |
|---|---|---|---|
| restDays | int | ✅ | ≥ 1 · 화면의 3일/1주/2주/직접선택을 **일수로 통일** · 상한 없음(✅자체 결정 — 제한 생기면 검증 추가) |

**서버**: `user_rest` 행 생성 — `rest_start_date = 오늘`, `planned_resume_date = 오늘 + restDays`
휴식 중엔 챌린지가 없으므로 한도 체크·미입력 알림·미니 챌린지는 자연히 없음(별도 상태 전이 불필요).

**응답 `201 Created`**

```json
{ "restId": 3, "restStartDate": "2026-07-06", "plannedResumeDate": "2026-07-13" }
```

**에러**

| 코드 | 상황 |
|---|---|
| 400 | restDays < 1 |
| 401 | 인증 실패 |
| 409 | 이미 휴식 중(종료 안 된 `user_rest` 존재) · **진행 중(IN_PROGRESS) 챌린지가 있으면 409** — ✅화면 확정(휴식 진입점 = 결과 화면뿐, 2026-07-07) |

> **배타 규칙(반대 방향, ✅자체 결정)**: 휴식 중에 `POST /challenges`(새 챌린지 생성)가 오면 **휴식을 자동 종료**(`actual_resume_date = 오늘`)하고 생성 진행 — "다시 챌린지 시작하기" 흐름. "진행 중 챌린지 + 열린 휴식" 동시 상태는 존재하지 않게 유지(만약 데이터가 꼬이면 `GET /current`는 **진행 중 챌린지 우선**).

## 2. `POST /api/rests/resume` — 복귀 / 더 쉬기 🔒 ⚠️

대응 화면: 복귀 팝업("다시 돌아오신 걸 환영해요!") — 세 선택지를 이 API 하나로 처리. 복귀는 "재개"가 아니라 **휴식 종료 기록**이며, 새 챌린지 생성은 별도로 `POST /challenges`.

**요청 바디**

| 필드 | 타입 | 필수 | 제약 / 설명 |
|---|---|---|---|
| when | string | ✅ | `NOW`(지금 바로) / `TOMORROW`(내일부터) / `EXTEND`(조금 더 쉴게요) |
| extendDays | int | 조건부 | ≥ 1, `when=EXTEND`면 필수 · ✅자체 결정: 기간 재선택 → 예정일 연장 |

**서버 동작 (when별)**

| when | 동작 |
|---|---|
| `NOW` | `actual_resume_date = 오늘` — 휴식 종료. 클라는 챌린지 생성 화면으로 이동 |
| `TOMORROW` | `actual_resume_date = 내일` — 내일부터 휴식 종료로 취급(오늘은 휴식기 홈 유지) |
| `EXTEND` ⚠️ | `planned_resume_date += extendDays` — 휴식 계속 |

**응답 `200 OK`**: `{ "restId": 3, "resumeDate": "2026-07-07" }` (`EXTEND`면 `{ "restId": 3, "plannedResumeDate": "..." }`)

**에러**: 400(when 오류 · EXTEND인데 extendDays 없음) / 401 / 404(휴식 중 아님).

## 3. 휴식 중의 `GET /challenges/current` 응답

휴식 중이면 current가 404가 아니라 `200 OK`로 휴식기 홈 데이터를 준다(진행 중 챌린지가 있으면 그쪽 우선). **위젯도 current 재사용 예정**(팀 협의).

| 유저 상태 | 응답 |
|---|---|
| 진행 중 챌린지 있음 | 기존 응답 그대로(`API명세_본챌린지.md` §2) |
| **휴식 중** | `200 OK` — `challenge: null` + `rest` + `keptRecords` |
| 챌린지도 휴식도 없음 | 404 (기존 정책 유지) |

```json
{
  "challenge": null,
  "rest": { "restStartDate": "2026-07-06", "plannedResumeDate": "2026-07-13" },
  "keptRecords": { "savedAmount": 68200, "maxStreak": 14 }
}
```

- `keptRecords` = **직전 종료 챌린지의 결과**(총 절약·최고 연속 — 휴식기 홈 표시값, 저장 없이 계산).

## 잠정 / 확정 요약

| 항목 | 현재 상태 |
|---|---|
| 휴식의 의미 | ✅ 챌린지 사이 공백(유저 단위) — 보관 기록 = 직전 결과, 진입점 = 결과 화면(화면 확정) |
| 진행 중 휴식 진입 | ✅ 불가(409) — 진입점이 결과 화면뿐(2026-07-07 화면) |
| 휴식 중 새 챌린지 생성 | ✅ 휴식 자동 종료 후 생성 진행 · current는 진행 중 우선 (자체 결정) |
| 휴식 상한·횟수 | ✅ 무제한 — 제한 생기면 검증 추가 (자체 결정) |
| "조금 더 쉴게요" | ✅ 기간 재선택 → `planned_resume_date += extendDays` (자체 결정) |
