## `POST /api/challenges/{id}/give-up` — 중도 포기 🔒

대응 화면: 진행 중 챌린지 "그만두기".

**서버**: 대상 챌린지(IN_PROGRESS)를 `status = FAIL`로 즉시 종료. `end_date` 경과 조건과 무관하게 확정 → 이후 `GET /{id}/result` 조회 가능(`API명세_본챌린지.md` §4 result의 status 규칙에 대한 예외 경로). `end_date`는 원래 목표 기간 그대로 보존(자체 결정 — 기록 유지, 필요 시 PM 확인). 요청 바디 없음.

**응답 `200 OK`**

```json
{ "challengeId": 1, "status": "FAIL" }
```

**에러**

| 코드 | 상황 |
|---|---|
| 401 | 인증 실패 |
| 403 | 남의 챌린지 |
| 404 | 챌린지 id 없음 |
| 409 | 이미 종료됨(IN_PROGRESS 아님) — `CHALLENGE_NOT_IN_PROGRESS` |

> ⚠️ **구현 시 주의 — 재계산과의 상호작용**: 종료 후 기간 내 지출을 수정하면 결과를 기록 기준으로 재계산하는 규칙(0714 확정)이 있는데,
> 포기의 FAIL은 기록에서 계산된 결과가 아니라 유저 선언이다. 표식(예: 종료 사유 컬럼) 없이 구현하면
> "포기한 챌린지의 지출을 수정했더니 기록상 전부 성공이라 SUCCESS로 부활"하는 버그가 된다 — 포기 챌린지는 재계산에서 제외할 것.
