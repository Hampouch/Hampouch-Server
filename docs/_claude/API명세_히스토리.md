## `GET /api/challenges/history` — 지난 챌린지 리스트 🔒 (마이페이지)

대응 화면: 마이페이지 "지난 챌린지". **종료된(SUCCESS/FAIL) 챌린지 목록**만 반환(IN_PROGRESS 제외 — 진행 중은 `current`). 로그인 유저 소유분, `endDate` 내림차순(최근 먼저).

> ⚠️ **0717 피그마 실측(스크린디자인 마이페이지 클러스터 — "지난 챌린지" 빈 상태 + "지난 챌린지 기록" 리스트 2장) — 시안과 현행 응답의 어긋남, 질문목록 12번 등록:**
> ① 시안 리스트 **맨 위에 "진행중" 배지 카드**가 있음("2/14" 칩, 종료일 없이 `2026.05.15.~`). 현행 서버는 IN_PROGRESS 제외 —
>   안드가 홈 `current`를 재사용해 맨 위 카드만 따로 그리면 현행 유지, 히스토리 응답 하나로 다 그리면 포함으로 변경(수정 작음).
> ② 시안 카드 표기 = 상태 배지 · "N일 챌린지 (기간)" · **"n/14" 칩** · **하루 한도 N원** · 총 절약 +N원. 현행 응답에 **칩의 n(성공 일수로 추정)과 dailyLimit이 없음** —
>   n이 성공 일수면 successDays 필드 추가(집계는 이미 계산 중이라 얹기만 하면 됨), 하루 한도는 dailyLimit 추가 필요(#7 조정 도입 시 클라 파생 계산 불가라 서버 제공이 안전).
>   시안 카드에 budgetTotal·actualSpent 표기는 없음(내려보내는 건 무해라 유지).
> 빈 상태 문구 "아직 마무리 한 챌린지가 없어요."는 빈 배열 200(404 아님) 설계와 정합 ✅.

**응답 `200 OK`** (기록 없으면 `items: []`)

```json
{
  "items": [
    { "challengeId": 12, "status": "SUCCESS",
      "startDate": "2026-05-01", "endDate": "2026-05-14", "durationDays": 14,
      "budgetTotal": 280000, "actualSpent": 211800, "savedAmount": 68200 },
    { "challengeId": 8, "status": "FAIL",
      "startDate": "2026-04-01", "endDate": "2026-04-14", "durationDays": 14,
      "budgetTotal": 210000, "actualSpent": 224000, "savedAmount": 41000 }
  ]
}
```
> 요약 필드는 `ChallengeDay` 집계(조회 시 계산) — `actualSpent`/`savedAmount`는 `EXPENSE`(외부) 의존, 연동 계약 전엔 시드. 각 챌린지 상세는 `GET /{id}/result` 재사용.
> `status`는 종료 시점에 확정·저장된 값(본챌린지 §4 status 규칙). 아직 한 번도 종료된 챌린지가 없으면 빈 배열.
>
> 구현하며 확정한 세부(0717 자체 결정):
> - **만료 후 미확정 챌린지도 포함** — status 확정은 배치 없이 최초 계산 시 저장(§4 lazy)이라, 기간이 끝났는데
>   결과 화면(`/result`)을 안 연 챌린지는 DB가 IN_PROGRESS로 남는다. 그대로 필터하면 방금 끝난 챌린지가
>   리스트에서 빠지므로, **히스토리 조회 시점에 §4와 같은 규칙으로 확정한 뒤 조회**한다.
> - **상태 필터는 `IN (SUCCESS, FAIL)` 명시** — "IN_PROGRESS 아닌 전부"로 두면 상태 신설 시(배틀 무효 이식
>   VOID 예정 — 0715 PM 확정) 자동으로 새어 들어온다. 무효 챌린지의 리스트 표시 여부는 미정(질문목록 11번)이라
>   답 나올 때까지 새 상태는 기본 비노출.
> - **`endDate` 같으면 id 내림차순**(나중에 만든 것 먼저) — 정렬을 결정적으로 만드는 보조 기준.
