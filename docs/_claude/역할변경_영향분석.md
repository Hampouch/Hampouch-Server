## 전체 분담표 (원문 그대로)

### 정일혁
- 온보딩 : 목표 식비 및 목표, 월급 등 정보 입력
- 홈 + 본 챌린지 : 온보딩 설정 목표 따른 현황 / 전날 + 다음날 상태 반영 / 지출 통계 따른 주의 or 소비 상태 알림(홈 화면) / 미니 챌린지 내보내기
- 위젯
- 미니 챌린지 : 완수 여부 체크
- 챌린지 결과 화면 : 분석과 유사하나 소비 습관 AI 진단 기능? / 새 챌린지 설정

### 김나연
- 로그인 : 일반 메일 로그인 / 소셜 로그인 / 회원가입 시 이메일 인증 / 비밀번호 찾기 기능 / refresh token 관리
- 게시판 : 게시글(사진 첨부 가능) / 댓글 / 게시판 카테고리 분리 / 조회수 / 추천 비추천 기능 / 정렬 / 기타 게시판
- 인프라

### 김령준
- 일일 지출 금액 입력 화면 : 금일 지출, 감정 태그, 메모, 사진
- 지출 상세 화면 : 일간 / 주간 / 월간 소비 경향 확인 / 식비 조정
- 지출 분석 화면 : 종류(외식, 디저트, 카페, 배달)별 식비 / 태그된 감정별 식비 / 요일별 식비 / AI의 식비 분석 / 월별 식비 추이
- 햄배틀 : 1 vs 1, group 분리 / 벌칙 태그 / 아이디 기반 초대 알림 + 링크 공유 / 시작일 기준 참여 인원 체크 / 진행 현황 따른 챌린지 목록 분리
- 마이페이지 : 닉네임 / 프로필 사진

### 보류
- 알림: 알림 생성 / 읽음 처리 / 목록

## 분담표로 해소된 기존 미결

| 기존 미결 | 해소 내용 |
|---|---|
| **EXPENSE(지출 데이터) 담당 없음** | ✅ **령준 확정** — 일일 지출 입력(금액·감정 태그·메모·사진) + 상세 + 분석 전부 령준. 챌린지 판정에 필요한 `{날짜·금액·종류·감정}`이 령준 데이터에 다 있음(종류=외식/디저트/카페/배달, 감정 태그). 남은 건 **연동 방식**(서버팀 계약)뿐 |
| **통합 인증·인사이트 리포트 분담 누락?** | ✅ 통합 인증 = 나연(로그인·refresh token·인프라), 인사이트 리포트 ≈ 령준(지출 분석 화면) |
| **유저 식별** | 나연 로그인(JWT + refresh token) 전제 유지 — 기존 가정과 일치 |
| **알림 형태(푸시?)** | 알림 도메인(생성·읽음·목록)은 **보류** → 홈 "소비 상태 알림"은 푸시가 아니라 **홈 화면 표시**로 해석 |

|---|---|---|
| 온보딩: 목표 식비·목표 입력 | `POST /challenges`(기간·예산·약한 카테고리)로 커버 | ✅ 기존 커버 |
| 온보딩: **월급 등 정보 입력** | 월급**날**(`paydayDay`) 저장으로 커버 — 월급 **금액**은 화면에 입력 없음 확인(2026-07-06) → 저장·API 없음 | ✅ 해소(구 Q3) |
| 홈: 온보딩 목표 따른 현황 | `GET /challenges/current`(progress 집계)로 커버 | ✅ 기존 커버 |
| 홈: **전날 + 다음날 상태 반영** | 의미 불명 — (a) 전날 판정·다음날 표시라면 current/calendar 응답으로 커버 가능 (b) 전날 기록 수정이라면 `POST /days` upsert가 이미 허용 | ❓ PM Q4 |
| 홈: **지출 통계 따른 주의/소비 상태 알림** | **신규** — 소비 상태 판정 로직 + 홈 응답 필드(또는 별도 API). 기준은 와이어프레임 v2로 확정(여유/주의/위험, 남은 한도 비율). 경고 카드 세부만 Q11 | 🆕 기준 확정 |
| 홈: **미니 챌린지 내보내기** | 의미 불명 (홈→미니 챌린지 진입? 공유? 노출 제거?) — 서버 작업 유무 자체가 여기 달림 | ❓ PM Q6 |

| 결과: **소비 습관 AI 진단(?)** | **신규(미확정)** — 분담표 원문에도 `?`. 확정 여부·형태 미정. 참고: 령준에게 "AI의 식비 분석"이 있어 **AI 호출 인프라를 공용화할지** 서버팀 협의 대상 | ❓ PM Q7 |
| 결과: 새 챌린지 설정 | `POST /challenges` 재사용. 추천 목표 '기준'은 기존 PM Q2 그대로 | ✅ 기존 커버 |

## 결론

- **기존 구현물(본 챌린지 5개 API·엔티티·판정/결과 로직)은 전부 그대로 유효** — 무효화된 것 없음, feat/1 작업 계속.
- 최대 미결이던 **지출 데이터 출처가 령준으로 확정** → 남은 건 PM이 아니라 **일혁↔령준 연동 계약**(공유 DB 직접 조회 vs 내부 API vs 령준 측이 `POST /days` 호출). `POST /challenges/{id}/days`의 호출 주체가 이 계약에서 결정됨.
- 신규 서버 작업 후보: ① 홈 소비 상태(판정 로직+응답) ② 미니 챌린지 완수 체크 ③ AI 진단(미확정). (④ 온보딩 월급 저장은 2026-07-06 해소 — 화면에 입력 없음 → 작업 아님)
- **블로커 아님** — 신규 항목은 전부 질문 답변 전에도 본 챌린지 마무리·스텁으로 우회 가능. 질문은 `PM_질문목록.md`에 누적해 두고 모아서 묻는다.

## 진행 순서 (제안)

1. 본 챌린지 Phase 1 마무리 (기존 계획 그대로)
2. 미니 챌린지 완수 체크 — 정의·목록 출처 확인 전엔 시드+스텁
3. 홈 소비 상태 알림 — 령준 지출 연동 계약 + 판정 기준 확정 후 (그 전엔 응답 필드만 자리 잡기 가능)
4. AI 진단 — 확정되면 착수 (령준 AI 식비 분석과 인프라 공용화 검토)
