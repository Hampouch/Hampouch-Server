## 1. 확정된 것 (설계에 바로 반영 가능)

### 홈 소비 상태 기준 — 기존 질문 5 해소 ✅
- 상태 3단계: **여유(70%↑) / 주의(30~70%) / 위험(30%↓)**
- 기준값 = **오늘 남은 한도 ÷ 하루 한도** (홈 3종 수치로 검증: 18,400/25,000≈74% 여유 · 12,000/25,000=48% 주의 · 3,500/25,000=14% 위험)
- 형태 = 홈 화면 표시(푸시 아님)
- 위험 상태에서 경고 카드 노출: ① "목표 금액 너무 빡셌나요? 7일 연속 한도 초과 → 조정하면 계속할 수 있어요" ② "배달 주의 구간이에요! 이번 주 배달 식비 18,000원" — 세부 기준은 Q11, '조정' 기능은 Q10

### 전체 카테고리 확정 ✅
- **카페/음료 · 디저트 · 배달 · 술자리 · 편의점 간식 + 직접 추가**
- 지출 입력 화면 칩과 약한 카테고리가 같은 리스트 → 서버: 기본 5종 + 자유 입력(**닫힌 enum 아님**, String 유지가 맞음)

### 감정 태그 유지 확인 ✅ (지출 입력 = 령준 화면)
- 스트레스 / 보상 / 귀찮아서 / 그냥 먹고 싶어서 / 직접 입력 + **건너뛰기 가능**
- → `emotion` **null 허용**. 결과 화면 감정 비율 계산 시 무태그 지출은 모수에서 제외(자체 결정)
- 지출 입력이 '식비만'으로 확정 → 그날 지출 합계 = 식비 합계 (판정 로직 단순 유지)

### 미입력일 처리 — 해소 ✅ (0630 회의: **미입력 = 0원 가정**)
- 기록 없는 날 = 0원 지출 → `SUCCESS` 취급(행 미생성이어도 집계 시 0원으로 계산) · 매일 저녁 리마인더로 입력 유도
- 리마인더의 "오늘은 안 썼어요!" 버튼 = 0원 **확정 입력**(가정이 아니라 명시적 기록)
- 알림 문구 "오늘 안 하면 7일 연속이 끊겨요"는 기록 습관 넛지로 해석 — 판정(0원=성공)과 별개

## 2. 신규 기능: 휴식 — ⚠️ 2026-07-06 재해석: "챌린지 사이의 공백"

> **재해석(일혁 확인 + 화면 근거)**: 휴식은 진행 중 챌린지의 일시정지(PAUSED)가 아니라,
> **챌린지가 없는 기간을 명시적으로 선택하는 유저 상태**다. 근거: ① 휴식기 홈의 보관 기록
> **+68,200원·최고 연속 14일 = 성공 결과 화면 숫자와 일치**(진행 중 수치가 아니라 직전 완주 결과)
> ② 복귀 문구가 전부 "다시 **시작**"(재개 아님) ③ 본챌린지는 원래 항상 있는 게 기본이라 "안 만들고 쉼"이 필요.
> → **PAUSED 상태 불필요 · 종료일 연장 질문(구 Q9-①) 소멸 · 휴식은 유저 단위(`user_rest`)**

화면에서 확정된 동작:
- **휴식 시작**: 기간 선택(3일 / 1주 / 2주 / 직접 선택) → 복귀 예정일 존재
- **휴식 중**: 하루 한도 체크·미입력 알림 없음(챌린지가 없으니 자연 소멸), 홈이 휴식기 화면으로 전환, **직전 챌린지 결과**(절약 금액·최고 연속)를 보관 기록으로 표시
- 휴식 중에도 가계부(지출 입력)·커뮤니티 등 다른 기능은 정상
- **복귀**: 예정일 도래 시 팝업 — "지금 바로 시작" / "내일부터" / "조금 더 쉴게요" → 새 챌린지 생성으로 유도

서버 영향 (재해석 기준):
- `user_rest` 테이블(유저 단위: 시작일·복귀 예정일·실제 복귀일) — challenge와 무관
- `ChallengeStatus`는 IN_PROGRESS/SUCCESS/FAIL **그대로** (PAUSED 철회)
- `GET /current`: 휴식 중이면 `challenge: null` + `rest` + `keptRecords`(직전 종료 챌린지 결과 — 저장 없이 계산)
- 미니 챌린지: 휴식 중엔 본 챌린지가 없으므로 자동으로 없음(하위 구조 그대로)
- **미정 → Q9(재편)**: ① 진행 **중**에도 휴식 진입 가능? 그 경우 기존 챌린지는 **중단** 처리(별도 status? FAIL?) ② 휴식 횟수·기간 제한 ③ 복귀 예정일 갱신 규칙("조금 더 쉴게요") — 구 블로커(종료일 연장)는 소멸

## 6. 추가 캡처: 미니 챌린지 화면 (2026-07-06)

### 확정된 것

- **출처 = 둘 다** (Q8 핵심 해소): ① **추천 미니 챌린지** — 공용 목록, 기간 탭(오늘만/3일/7일/14일/31일)으로 필터, "+추가하기"로 참여 ② **나만의 챌린지 직접 만들기(커스텀)** — 이름·기간·이모지(선택) 입력.
- **기간형 + 일 단위 반복 체크** (Q12 핵심 해소): 항목마다 기간이 있고(예: 2/7일), **매일 체크**하는 구조. "오늘의 달성 현황 N/M 완료" 도넛 + 항목별/전체 **연속 달성**(3일째 등) 표시 → **일별 체크 기록 테이블 필요**, 1회성 완수 모델 폐기.
- **날짜 스트립**(05.06 / [05.07] / 05.08): 홈·미니 화면 상단에서 전날/다음날 이동 → **Q4 "전날+다음날 상태 반영"의 정체로 추정** — 조회 API에 date 파라미터로 대응.
- **홈 "오늘 나의 챌린지" 섹션 = 미니 챌린지** (일혁 확인): 홈에 미니 체크리스트 노출(이름·진행 n/기간·체크박스·전체 보기) → Q6 "내보내기"는 **홈 노출**을 뜻할 가능성 높음.
- **난이도(쉬움/보통/도전)**: 화면에 있으나 커스텀 생성부에 **"→ 난이도 부분 삭제" 주석** → 잠정 제외(삭제 범위는 Q14).
- 구버전 ERD(Untitled4)의 **기간·연속일 개념이 화면과 부합**했음을 확인 — 다만 추천(공용 정의)+커스텀 공존이라 **정의/참여 분리 구조는 유지가 맞음**.

### 설계 영향 (ERD·API 재편)

- 3테이블: `mini_challenge`(정의: 제목·기간·이모지·추천/커스텀) / `challenge_mini_challenge`(참여: 시작·종료 스냅샷, 본 챌린지 하위 확정) / `mini_challenge_day`(일별 체크, 해제=행 삭제).
- 집계(오늘 N/M·항목별 진행·연속)는 저장 없이 조회 시 계산 — 본 챌린지 철학과 동일.

## 7. 추가 캡처: 새 챌린지 설계·결과 보강·휴식 최신 문구 (2026-07-07)

### 새 챌린지 설계 화면(성공 후/실패 후) — "다음 챌린지 추천" 확정
- 흐름: 결과 화면(또는 휴식기 홈) → **새 챌린지 설계 화면**(포치의 추천이 프리필) → "이 챌린지 시작하기"(= `POST /challenges`) 또는 "처음부터 직접 설정할게요"
- 구성: **지난 챌린지 결과 요약**(목표/실제 + 태그: "60,000원 아낌"·"목표 대비 15%↓"·"28일 기록 유지" / 실패: "11,183원 초과"·"지난달보다 6%↑"·"**스트레스 45%**"·"**주말·배달 집중**") + **포치의 추천**(상황 맞춤 문구 + 기간·목표·하루 한도·집중 카테고리 프리필)
- → **추천 API 신설 필요**(`기능별 API명세 파일(휴식·중도포기·미니챌린지·한도조정·추천·집중카테고리)` §6-1). 태그 중 감정·요일 분석은 령준 지출 데이터 의존.
- 추천 수치가 0630의 "±10%"와 정확히 일치하지 않음(성공: 400,000→330,000·기간 유지 / 실패: 목표 170,000·기간 30→14일 단축·집중 1개로 축소) → 산정 기준·문구 생성(룰 vs AI)은 서버 회의 안건(Q2 연계)

### 새 발견 2건
- **"집중 카테고리"** — 약한 카테고리의 화면 명칭. 그런데 칩이 **배달/카페·음료/디저트/외식/술자리/편의점 간식(6종, 직접추가 없음)**으로 지출 입력-2의 7종(배달/외식/편의점/카페/간식/장보기/술자리+직접추가)과 다름 → Q9
- **하루 한도 12,143원 재등장** — 170,000÷14 = 12,142.86 → 화면은 **반올림**(12,143). 기존 자체 결정(floor=12,142)과 1원 차 충돌이 반복 → 자체 결정 철회, Q10으로 전환

### 결과 화면 보강 확인
- 성공/실패 화면에 소비 감정 분석·캘린더는 기존 설계(result API) 그대로 커버. "자세한 소비 지출 분석 보기" → 령준 분석 화면 진입(서버 작업 없음)
