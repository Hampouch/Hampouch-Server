# 구현 착수 점검 (Claude Code 핸드오프)

> 목적: **Claude Code가 현재 문서만으로 본 챌린지 서버 구현을 시작할 수 있는지** 점검.
> 결론: **핵심은 착수 가능.** 아래 🟡(권장 기본값으로 진행) + 🔴(스텁)만 처리하면 막힘 없음.
> 근거 문서: `본챌린지_백엔드_설계초안.md` · `ERD.mermaid` · `API명세_본챌린지.md`

---

## ✅ 바로 구현 가능 (확정)

- 판정 로직: `spent ≤ dailyLimit ? SUCCESS : OVER`
- 하루 한도: `floor(budgetTotal / durationDays)` (스냅샷 저장)
- 결과 계산: `savedAmount = Σ max(0, 한도−지출)`, `overAmount = Σ max(0, 지출−한도)`, 연속(streak)
- 엔티티 골격: `Challenge`, `ChallengeDay`, `ChallengeWeakCategory` (필드·타입은 ERD/설계초안)
- API 5개: 경로·요청/응답·상태코드 (API명세)
- 에러 포맷: 팀 공통 `{code, message, status, fieldErrors}` (400/401/403/404/409) — 나연 common `ErrorCode`/`GlobalExceptionHandler`, 챌린지 도메인은 코드 등록만(2026-07-07 교체)

## 🟡 Claude Code가 컨벤션으로 정하면 됨 (권장 기본값)

| 항목 | 권장값 |
|---|---|
| 패키지 구조 | `domain/challenge` 아래 `controller · service · repository · entity · dto` (레이어드) |
| Phase 1 의존성 | web, data-jpa, validation, mysql-connector, flyway (security는 스텁 단계 뒤로) |
| Enum 저장 | `VARCHAR` + `@Enumerated(STRING)` (MySQL ENUM 비권장) |
| varchar 길이 | category/emotion/status 등 `VARCHAR(30~50)` |
| 인덱스 | `unique(challenge_id, day_date)` · `challenge(user_id, status)`(current 조회용) |
| 타임존 | `Asia/Seoul` 기준 날짜 계산 |
| 시드 | 스텁 단계 테스트용 더미 `ChallengeDay` 생성 |

## 🔴 팀/PM 확정 전 — 스텁 처리 (→ 잠정표)

| 항목 | 스텁 | 확정처 |
|---|---|---|
| userId | 고정값(`1L`) 또는 임시 헤더 | 나연 |
| EXPENSE 유입 | `POST /days` 수동/시드 | 령준(연동 계약) |
| DB 공유/컨벤션 | 로컬 단독 스키마로 시작 | 팀 |
| 약한 카테고리 저장 단위 | 챌린지별 | ✅ 자체 결정(해소) |

## ⚠️ 보완 필요 (구현 전 한 줄만 결정)

1. ✅ **`status` 확정 시점 (결정됨)** — `GET /result` 조회 시 `end_date` 경과로 계산(전부 SUCCESS → SUCCESS, OVER 1+ → FAIL), 최초 계산 시 저장, 스케줄러 없음.
2. **동시 진행 챌린지 1개** 가정 → 생성 시 IN_PROGRESS 존재하면 409. (잠정표 5)

> 이제 ⚠️ 핵심 결정(status)은 완료. Claude Code는 ✅ + 🟡 기본값으로 **Phase 1(엔티티·판정·결과 API)**을 스텁 위에서 바로 구현 가능. (#2 동시 1개는 잠정표 가정 따름.)
