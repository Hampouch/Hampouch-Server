> 규칙: 질문이 생기면 여기 누적, 한 번에 모아서 묻는다. 블로커일 때만 일혁에게 알린다.
> **여기엔 열린 질문만 둔다** — 답이 나오면 확정 내용을 `결정기록.md`로 옮기고 지운 뒤 1부터 재정렬(참조 문서·코드 주석 동기 갱신).
> 0714 답변 반영분(카테고리 카드 70%·재계산·기록0건 성공·홈 미입력 포함·미니 독립 사용·건너뛰기)은 `결정기록.md` "0714 답변" 섹션.

1. **월급날 주기 모드 — 남은 정의** (0714 확정: 주기가 월급날로 맞춰짐 · 기간형은 일회성이라 무관 · 첫 주기는 부분 기간 가능 · 기간 선택↔날짜 고정 상호 배타 UI · 온보딩 입력은 하루당 목표 식비 — `결정기록.md` 0714 전체회의 섹션)
   - 주기가 돌 때마다 예산은 어떻게 리필되나 — 하루당 목표 × 그 주기 일수인가? (온보딩이 하루당 입력이라 "총액 고정 리필"과 다를 수 있음) 부분 첫 주기(가입~월급날 갭 "자동 목표" — 0714)도 같은 계산인가?
   - 주기는 언제까지 반복되나 — 유저가 끄기 전까지 무한? 종료(해지)는 어떻게 하나?
   - (PM 답 나오면 안드와 계약 협의) 상호 배타 확정에 따라 월급날 모드 생성 요청 재정의 필요 — durationDays 없이 paydayDay만 보내는 형태? (현 서버는 durationDays 필수로 받는 중첩 구조 — 월급날 동작 정의 확정 때 함께 변경)

2. **기간 만료 후 '챌린지 최종 종료'(finalize/lock)** (스크린디자인의 '지출 수정하기 / 챌린지 종료' 화면 — 디자이너 주석 "피엠님과 추가 논의 필요"로 디자인 자체 미확정)
   - 만료 후 "지출 수정 유예 → '챌린지 종료' 버튼으로 확정·잠금" 흐름이 확정인가?
   - 유예 기간의 상한은? 종료 버튼을 계속 안 누르면 어떻게 되나?
   - 잠금 후에는 지출 수정(과 그에 따른 결과 재계산 — 0714 확정)도 막히는 건가?
   - (확정되면 서버에 종료 확정 write API + 상태 전이 추가 — 확정 전 구현 보류)

3. **경고 카드 공통 노출 규칙** — "카드는 위험 홈(오늘 사용률 위험)에서만 노출"이 실제 디자인 의도인가? (현재 서버: 카드별 자기 트리거로만 발동 — GOAL_TOO_TIGHT는 오늘 사용률 무관, 판정 완료 구간 3일 연속 초과)용

4. **예산·하루 한도의 하한 (+ 무지출 챌린지 지원 여부)** — 서버는 budgetTotal ≥ 1만 검증 중이라, 저예산+장기간(예: 50원·100일)이면 버림 나눗셈으로 **하루 한도 0원 챌린지**가 성립한다(지출 0원인 날만 성공). 온보딩에 예산 최소 입력값이 있나? 서버가 "하루 한도 ≥ 1원" 같은 하한을 강제해야 하나?
   - 연관 질문: **예산 0원 = "무지출 챌린지"로 해석 가능**한데(지출 0원만 성공 — 실존하는 절약 방식) 지원 의도가 있는 기능인가? 지원한다면 UI 문구·절약액 표시(항상 0원) 기획 필요. 확정 전까지 서버는 0원 금지(@Min(1)) 유지 — 미입력 사고와 구분이 안 되는 값이라. (블로커 아님 — 현재도 계산은 0 방어로 동작)

4. **결과 화면 "하루하루 기록" 달력의 달 넘김** — 결과(성공/실패) 화면 속 도장 달력이 단일 월 그리드로만 그려져 있는데, 챌린지가 두 달에 걸치면(예: 6/20~7/19) 달 넘김 UI가 생기는지? (서버 §3 calendar는 year/month 파라미터라 어느 쪽이든 대응 가능 — 서버 영향 없음, 안드 구현 참고용)
