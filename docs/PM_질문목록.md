## PM에 물어볼 것

1. **월급날 리셋의 정확한 동작** — 기능 존재는 확인됨(0711 추가 답변). 남은 정의:
   - 월급날이 되면 **무엇이** 리셋되나? (주기를 월급날~월급날로 맞춤? 다음 챌린지 시작일만 월급날로 스냅? 예산만 리필?) : 주기가 월급날로 맞춰짐
   - **기간(durationDays)과의 관계** — 월 단위(≈30일) 전용인가, 7일 챌린지에도 체크 가능한가? (현재 화면은 독립 입력) : 기간은 일회성임
   - 주기를 맞추는 방식이면 **첫 주기는 부분 기간**(오늘~다음 월급날, 30일 미만)이 되나? : 첫 주기는 첫 월급날 전까지의 부분 기간 가능
   - 30일 챌린지 **중간에** 월급날이 끼면 어떻게 되나? 리셋 시 dailyLimit 재계산 기준은? : 기간으로 하는 건 위에서 말했다시피 일회성이라 월급날을 통해 주기 설정하는 거랑은 상관이 없음
   - (서버는 현재 `resetByPayday`/`paydayDay` 저장까지만 구현)

2. **집중 카테고리 경고 카드(WEAK_CATEGORY_ALERT)의 기준 금액·임계값·노출 구간** — 0711 답변("여유/주의/위험 퍼센티지만큼 해당 카테고리를 소비했을 때 뜸")에서 파생:
   - **분모(기준 금액)**: 우리 데이터 모델엔 카테고리별 예산이 없고 `budgetTotal`(전체)뿐 → **전체 예산 기준**일 수밖에 없음(확인만). : 전체 예산에서 차지하는 비율로 계산하는 거 맞다니까
   - **임계값**: 와이어프레임 텍스트엔 "카테고리에 예산의 **70%**"인데, 예시("배달만 18,000원")로 역산하면 **30%**(전체 6만 기준)에 맞음 → **30%인지 70%인지** 확정 필요(문서 내 불일치). : 70% 이상임
   - 카드가 뜨는 구간은 **'주의'부터**인가 **'위험'만**인가? (카테고리엔 위험 카드가 따로 없고 '주의' 단일 카드로 보임 — 맞나?): 주의, 위험이라는 단어가 헷갈리기는 하는데 아무튼 무조건 70퍼 이상일 때 카드를 띄우며, 내용도 주의로 일괄 

3. **종료 후 수정 시 결과 재계산 여부** — 0711 답변("지출·미니 둘 다 챌린지 기간 내 자유롭게 수정 가능")에서 파생:
   성공/실패가 이미 확정된 챌린지의 기간 내 지출을 나중에 고치면, **확정된 결과(status)와 결과 화면 집계도 다시 계산돼 바뀌나?** 아니면 최초 확정값 유지인가? : 다시 계산됨

4. **기록이 0건인 채 끝난 챌린지의 결과** — 미입력일=0원 규칙을 그대로 적용하면 "하루도 입력 안 한 챌린지 = 전원 성공"이 됨. 이대로 SUCCESS 처리인가? (현재 서버는 보수적으로 결과 미확정 처리 중): 성공 처리

5. **진행 중 홈 현황(progress)도 미입력일을 성공으로 포함해 보여주나** — 결과 화면은 "미입력일=0원=SUCCESS 포함"이 0630 확정(명세 §4, 서버 반영 완료 0711). 홈의 progress(successDays·절약액)는 명세 §2에 미입력 언급이 없음 — 현재 서버는 기록일만 집계. 결과와 홈의 숫자가 달라질 수 있는데 의도인가?: 미입력이 무조건 0원 처리 아님? 그러면 성공으로 해야 하는 거 아님?

6. **본 챌린지가 없는 상태에서도 미니 챌린지를 쓸 수 있나** — 0707 미니 독립화(유저 소유, 구조 확정)에서 파생된 미확정 지점: 쓸 수 있음
   - 본챌 미생성·휴식기·종료 후 상태에서도 미니 **생성·조회·체크**가 가능한가? (서버 설계는 독립화에 따라 "가능"으로 둠 — 본챌 관련 에러 조건 없음)
   - 화면상 미니 진입점이 홈(본챌 화면)이라면, 본챌 없는 상태에서 미니 화면에 들어가는 경로가 실제로 존재하나?:ㅇㅇ 챌린지 있었을 때처럼 홈 화면에 섹션이 그대로 존재해서 이용 가능
   - ※ "기간이 본챌을 넘어도 됨"은 독립화의 논리적 귀결로 처리 중(0707 제약 소멸) — 이 항목은 "본챌 부재 시 단독 사용"만 확인하면 됨.

7. **기간 만료 후 '챌린지 최종 종료'(finalize/lock) 동작 — 서버 write 엔드포인트 필요 여부** — 스크린디자인 전수 판독에서 확인(2026-07-12, sd_r1_c2 등):
   - 기간이 끝나면 바로 확정하지 않고 **지출 수정 유예 상태**('지출 수정하기' 가능)로 두었다가, **'챌린지 종료' 버튼**으로 최종 확정 → 이후 "식비 입력/수정 불가"로 잠금.
   - 이는 중도포기(give-up=즉시 FAIL)·`GET result`(읽기전용)와 **의미가 다른 별도 write 전이**(예: 만료 → PENDING_CLOSE → CLOSED). 현재 서버엔 이 종료 확정 액션이 없음.
   - ⚠️ **디자인도 미확정**: 해당 화면에 디자이너 주석 "피엠님과 추가 논의가 필요한 부분입니다. 확정시 붉은선 제거하겠습니다" + 붉은선 표시. → PM 확정 후에야 서버에 종료 확정 엔드포인트(+상태 전이·유예기간 규칙) 추가 가능. 확정 전엔 구현 보류.
   - 연계: **#3**(종료 후 지출 수정 시 결과 재계산 여부) — '유예기간 편집 → 확정 시 락' 모델이 #3의 답 형태와 직결. #3·#7을 함께 물을 것.

8. **본 챌린지 기간(durationDays) 선택지 정합** — 온보딩 기간 옵션이 **와이어프레임(7/14/30/직접)** 과 **스크린디자인(3/7/14/31/직접)** 에서 불일치(3일 옵션 유무 · 30↔31일). 서버 `durationDays` 검증 허용값에 직결 → 확정 목록 필요. (※ 미니 챌린지 기간옵션 불일치는 별건 — `와이어프레임v2_서버영향.md` Q14)
