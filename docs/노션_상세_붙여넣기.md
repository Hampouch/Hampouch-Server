▼▼▼▼▼▼▼▼▼▼  복사 시작  ·  붙여넣을 곳 = [challenge 1 — 챌린지 생성 · POST /api/challenges] 행  ▼▼▼▼▼▼▼▼▼▼

## Request
```json
{
  "durationDays": 30,
  "budgetTotal": 100000,
  "startDate": "2026-06-23",
  "resetByPayday": true,
  "paydayDay": 25,
  "weakCategories": ["카페", "배달", "편의점"]
}
```

## Response (201 Created · Location: /api/challenges/{id})
```json
{
  "code": "SUCCESS",
  "message": "요청이 성공했습니다.",
  "data": {
    "challengeId": 1,
    "dailyLimit": 3333,
    "startDate": "2026-06-23",
    "endDate": "2026-07-22",
    "status": "IN_PROGRESS"
  }
}
```

## Error Response
- 필드 누락·형식·범위 위반(durationDays 1~100 — 상한 100일은 0714 전체회의 확정), resetByPayday=true인데 paydayDay 없음 (400)
```json
{ "code": "VALIDATION_ERROR", "message": "입력값이 올바르지 않습니다.", "status": 400,
  "fieldErrors": { "durationDays": "100 이하여야 합니다." } }
```
- 이미 진행 중(IN_PROGRESS) 챌린지 존재 — 동시 1개 가정 (409)
```json
{ "code": "CHALLENGE_ALREADY_IN_PROGRESS", "message": "이미 진행 중인 챌린지가 있습니다.", "status": 409 }
```
- 토큰 없음/유효하지 않음 (401)

> 참고: 기간이 끝났는데 결과 화면을 안 열어 미확정으로 남은 챌린지는 생성을 막지 않는다 — "이미 진행 중인 챌린지가 있는가" 중복 검사보다 먼저 기록 기준으로 확정된다. 휴식 중이면 409가 아니라 열린 휴식을 자동 종료(actual_resume_date=오늘)하고 생성이 진행된다.

▼▼▼▼▼▼▼▼▼▼  복사 시작  ·  붙여넣을 곳 = [challenge 2 — 진행 중 챌린지 + 현황 · GET /api/challenges/current] 행  ▼▼▼▼▼▼▼▼▼▼

## Request
요청 바디 없음 (인증 헤더만). 진행 중이면 challenge/progress/consumption/warningCards/adjustment 5블록을 항상 함께 반환.

## Response (200 OK · 진행 중)
```json
{
  "code": "SUCCESS",
  "message": "요청이 성공했습니다.",
  "data": {
    "challenge": {
      "id": 1, "durationDays": 30, "startDate": "2026-06-23", "endDate": "2026-07-22",
      "budgetTotal": 100000, "dailyLimit": 3333, "status": "IN_PROGRESS"
    },
    "progress": {
      "elapsedDays": 5, "remainingDays": 25,
      "successDays": 4, "overDays": 1, "currentStreak": 2, "savedAmountSoFar": 4200
    },
    "consumption": {
      "todaySpent": 2000, "todayRemaining": 1333, "dailyLimit": 3333,
      "usageRate": 0.6, "character": "NORMAL", "alertLevel": "CAUTION"
    },
    "warningCards": [],
    "adjustment": { "usedCount": 0, "maxCount": 2 }
  }
}
```

## Response (200 OK · 휴식 중)
```json
{
  "code": "SUCCESS",
  "message": "요청이 성공했습니다.",
  "data": {
    "challenge": null,
    "rest": { "restStartDate": "2026-07-06", "plannedResumeDate": "2026-07-13" },
    "keptRecords": { "savedAmount": 68200, "maxStreak": 14 }
  }
}
```

## Error Response
- 진행 중 챌린지 없음(휴식도 없음) (404)
```json
{ "code": "NO_ACTIVE_CHALLENGE", "message": "진행 중인 챌린지가 없습니다.", "status": 404 }
```
- 인증 실패 (401)

> 참고: character = FULL/NORMAL/SKINNY, alertLevel = NONE/CAUTION/DANGER — 경계 둘 다 30/70(0714 통일, 필드는 분리 유지). progress 집계 구간은 기본 "시작일~어제"이고, 그 사이 기록 없는 날은 0원 지출(성공)로 간주해 센다(결과 화면과 같은 규칙 — 0714). 오늘은 아직 하루가 안 끝났으므로 기본 제외하되, 오늘 지출을 이미 입력했다면 오늘까지 포함해 계산. warningCards는 현재 GOAL_TOO_TIGHT(3일 연속 한도 초과)만 구현 — 오늘 사용률과 무관하게 발동, 미기록일이 지나가면 연속이 끊겨 사라짐. adjustment.usedCount는 조정 구현 전 0 고정. 위젯도 이 API 재사용 예정.
>
> 휴식 중 응답: challenge는 null을 명시(안드가 이 null로 휴식 모드 판별), 진행 5블록은 아예 안 실림. keptRecords = 휴식기 홈 "보관 중인 내 기록"의 두 값 — 현행은 직전(가장 최근에 만든) 종료 챌린지의 총 절약·최고 연속을 결과 화면과 같은 규칙으로 저장 없이 계산(그 결과 화면에서 본 숫자와 일치). ⚠️시안 라벨("누적 절약 금액")이 역대 챌린지 전체 누계로도 읽혀 집계 대상은 확인 중 — 어느 쪽이어도 응답 필드는 그대로. 종료 챌린지가 없으면 0·0(잠정 — 온보딩 건너뛰기로 챌린지 없이 시작한 유저가 휴식을 열면 실제로 나올 수 있는 값). 진행 중 챌린지가 있으면 항상 진행 중 응답이 우선.

## Request
요청 바디 없음. 종료(SUCCESS/FAIL) 챌린지만, endDate 내림차순(최근 먼저).

```json
{
  "code": "SUCCESS",
  "message": "요청이 성공했습니다.",
  "data": {
    "items": [
      { "challengeId": 12, "status": "SUCCESS",
        "startDate": "2026-05-01", "endDate": "2026-05-14", "durationDays": 14,

        "startDate": "2026-04-01", "endDate": "2026-04-14", "durationDays": 14,
        "budgetTotal": 210000, "actualSpent": 224000, "savedAmount": 41000 }
```

- 인증 실패 (401)

> endDate가 같으면 나중에 만든 챌린지가 먼저 온다(보조 정렬).

▼▼▼▼▼▼▼▼▼▼  복사 시작  ·  붙여넣을 곳 = [challenge 7 — 중도 포기 · POST /api/challenges/{id}/give-up] 행  ▼▼▼▼▼▼▼▼▼▼

## Request
요청 바디 없음. 진행 중 챌린지를 즉시 FAIL로 종료(0707: 도중 중단=실패).

## Response (200 OK)
```json
{
  "code": "SUCCESS",
  "message": "요청이 성공했습니다.",
  "data": { "challengeId": 1, "status": "FAIL" }
}
```

## Error Response
- 이미 종료됨(IN_PROGRESS 아님) (409)
```json
{ "code": "CHALLENGE_NOT_IN_PROGRESS", "message": "이미 종료된 챌린지입니다.", "status": 409 }
```
- 남의 챌린지 (403) · 챌린지 id 없음 (404) · 인증 실패 (401)

> 참고: FAIL 확정 후 GET /{id}/result 조회 가능. end_date는 원래 목표 기간 보존.
> 포기의 FAIL은 유저 선언이라, 이후 기간 내 지출을 수정해도 재계산(0714 규칙)으로 SUCCESS로 되살아나지 않음(재계산 제외). 기록 수정 자체는 허용.
> end_date가 지났는데 미확정(결과 화면 미조회)인 챌린지에 포기가 오면, 기록 기준 확정이 먼저 적용된 뒤 409 — 완주 결과가 뒤늦은 그만두기로 FAIL이 되지 않음. end_date 당일까지는 포기 가능.

## Response (200 OK)
```json
{
```
